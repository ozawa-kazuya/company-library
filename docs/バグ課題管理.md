# 社内図書貸出管理システム バグ・課題管理

| 項目 | 内容 |
|------|------|
| 対象 | 開発担当・運用担当・管理者 |
| 最終更新 | 2026年9月 |

**JIRA、Trello、Notion、GitHub Issues はアプリに組み込んでいない。** 障害の切り分け・修正・本番反映は [バグ対応書](./バグ対応書.md)。記録の項目は同資料 **第9章** のテンプレートである。どの社内ツールに貼るかは運用側の判断であり、コードからチケットは作らない。

---

## 1. 何を使うか

| 種類 | やり方 |
|------|--------|
| **不具合（バグ）** | [バグ対応書](./バグ対応書.md)。優先度は P1〜P4。テンプレートをチケットまたは社内 Wiki にコピー |
| **機能要望** | バグ対応書の対象外。要件として別管理（[バグ対応書 第5章](./バグ対応書.md)） |
| **日常の点検** | [定期メンテナンス](./定期メンテナンス.md)（課題トラッカーではない） |
| **例外の記録** | CloudWatch Logs（[エラートラッキング](./エラートラッキング.md)）。Sentry からチケットは作らない |

リポジトリに `.github/ISSUE_TEMPLATE` は無い。Slack の期限切れ通知は貸出業務であり、バグ管理ではない（[外部サービスAPI](./外部サービスAPI.md)）。

識別子の例は `BUG-YYYY-MM-DD-001`（[バグ対応書 第9章](./バグ対応書.md)）。必須の採番システムは無い。

---

## 2. 使わないもの

| 製品 | 使用 |
|------|------|
| JIRA / Linear / Backlog / Redmine | アプリ連携なし。社内で別途使う場合も、このリポジトリからは送らない |
| Trello / Notion / Asana | 同上 |
| GitHub Issues / GitHub Projects | テンプレート・自動化なし |
| Sentry → チケット自動起票 | Sentry 未導入 |

パスワードや Token をチケットに貼らない（[環境変数とシークレット](./環境変数とシークレット.md)）。
