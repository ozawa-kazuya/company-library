# 社内図書貸出管理システム 共有アカウントの管理方法

| 項目 | 内容 |
|------|------|
| 対象 | 管理者・運用担当 |
| 最終更新 | 2026年9月 |

**図書システムに「共有アカウント」機能は無い。** 1 人につき 1 つの社員番号（`user_code`、UNIQUE）で登録する。貸出・返却・期限切れ Slack はすべてそのユーザーに紐づく。窓口 PC でも、操作する人が自分のアカウントでログインし、終わったらログアウトする。

---

## 1. なぜ共有しないか

| 共有すると起きること | 理由 |
|----------------------|------|
| 誰が借りたか分からない | `loans.user_id` がアカウント単位 |
| 同じ ISBN を同時に複数人が借りられない | 「同時に 1 冊まで」は **そのアカウント** に対する制限 |
| ログイン失敗で全員がロック | 失敗 5 回はアカウント単位 |
| Slack DM・再設定メールが一人に集中 | メールアドレスはユーザーに 1 つ（UNIQUE） |
| 除名すると全員の履歴が消える | [マニュアル](./マニュアル.md) |

SSO / Active Directory / ゲスト用ロールは無い。

---

## 2. 運用で守ること

| 場面 | やり方 |
|------|--------|
| 入社 | 利用者登録で本人の社員番号（[マニュアル](./マニュアル.md)） |
| 窓口・共用 PC | 自分の社員番号でログイン → 作業後にログアウト。前の人の画面を使い回さない |
| 管理者 `001` | 個人の管理者アカウント。図書室の「共用管理者」として配らない |
| 初期パスワード | 既定 `password` のまま共有しない。初回変更させる（[シークレット管理](./シークレット管理.md)） |
| すでに共用している | やめて個人アカウントを発行する。貸出中は本人返却が必要 |

セッションは Cookie（既定 120 分）。別ブラウザで同時ログインを禁止する仕組みはアプリに入れていない。だからこそパスワードを共有しない。
