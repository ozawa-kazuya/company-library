# 社内図書貸出管理システム 主要機能一覧

| 項目 | 内容 |
|------|------|
| 対象 | 開発担当・運用担当・管理者 |
| 最終更新 | 2026年9月 |
| 状態の基準 | 本サーバーで使える機能 |

画面の操作は [マニュアル](./マニュアル.md)、設計 ID（F-01 など）は [基本設計書 第3章](./基本設計書.md) です。仕様と設計の地図は [システム仕様書と設計書](./システム仕様書と設計書.md) です。OpenAPI は [API仕様](./API仕様.md) です。DB アクセスは [SQLとORM方針](./SQLとORM方針.md) です。セキュリティは [セキュリティ対策](./セキュリティ対策.md) です。

## 1. 全体像

ブラウザ向けの **モノリシック Web アプリ** です。外部公開の REST API サーバーではありません。画面は Inertia.js で Laravel と React が一体です。

| 分類 | 概要 |
|------|------|
| ユーザー認証 | 社員番号 + パスワード。セッション Cookie |
| 貸出業務 | 本棚・借りる・返す・場所制限 |
| 管理 | 資料・利用者・検索・期限切れ |
| API 連携 | 書誌・表紙の外部取得、Slack、メール |
| バッチ | cron による期限切れ Slack（毎分） |

```
ログイン
  ├─ 一般社員 → 本棚 / 貸出 / 返却
  └─ 管理者   → 管理メニュー / 集計（本棚は使わない）
         │
外部 API（ISBN 登録時）  バッチ（cron → Slack）
```

## 3. ユーザー認証

| 項目 | 内容 |
|------|------|
| 方式 | セッション認証（Laravel Breeze）。Cookie |
| ログインキー | `user_code`（社員番号。画面は数字 3 桁。例 `001`） |
| パスワード | bcrypt。新規は初期値（既定 `password`） |
| 権限 | `role` が `user` または `admin` |
| ログイン後 | 一般 → `/dashboard`、管理者 → `/admin/menu` |
| 初回 | 初期パスワードのままなら変更画面以外は使えない（`EnsurePasswordChanged`） |
| 管理者画面 | `admin` ミドルウェア。一般は入れない |
| 公開登録 | `/register` は Breeze 由来で残る。運用上の利用者追加は管理画面 |

パスワード忘れ:

1. ログイン画面の再設定メール（`MAIL_*` が届くこと）
2. 管理者が除名画面からパスワード再発行

OAuth / SSO / JWT 公開 API はありません。

## 4. 貸出・返却（業務）

| 機能 | 概要 |
|------|------|
| 本棚 | ISBN 単位でグループ表示。在庫は冊数。表紙と題名 |
| 借りる | 未貸出の 1 冊を `copy_number` 順で割り当て。同じ ISBN を同時に複数冊は不可 |
| 返す | 自分の未返却レコードに `returned_at` を入れる |
| 場所制限 | サーバー側ミドルウェア。社外では借りる・返すボタンが使えない。閲覧は可 |
| 期限 | 7 日 / 14 日 / 1 ヶ月（当日終了）。延長なし。1 分は Slack 確認用 |

正の貸出状態は `loans.returned_at IS NULL` です。`books.status` は補助です。

## 5. 管理機能

| 機能 | 概要 |
|------|------|
| 資料登録 | `GET /admin/books/lookup` で ISBN 検索（JSON）→ 台帳へ追加 |
| 全資料編集 | 一括更新。表紙なしだけ外部 API で再取得も可 |
| Excel | 在庫上書き時は既存表紙を残す実装あり |
| 表紙アップロード | 管理者がファイル指定 → `/covers/{uuid}` |
| 利用者 | 一括登録、除名、パスワード再発行 |
| 検索 | 資料の貸出状況と利用者の借用状況 |
| 期限切れ | 一覧とバッジ。この画面から代理返却はできない |

`/admin/loans` は期限切れ画面へリダイレクトするだけです。

## 6. API 連携

詳細は [外部サービスAPI.md](./外部サービスAPI.md) です。

自前の公開 API は提供しません。アプリが外部を呼ぶ連携と、画面用の内部 JSON です。

### 6-1. 外部（サーバーから）

| 先 | いつ | 内容 |
|----|------|------|
| OpenBD | 資料登録・表紙再取得 | 書誌・表紙（優先） |
| 版元ドットコム | 表紙が無いとき | 書影 |
| Open Library | その次 | 書影 |
| Google Books | 書誌・表紙の補完 | ISBN / 題名 |
| 国立国会図書館 | 題名から ISBN | OpenSearch |
| Slack Webhook | バッチ | 管理チャンネルへ期限切れ一覧 |
| Slack Bot API | バッチ | 一般利用者へ DM（メール一致時） |
| メール | パスワード再設定 | `MAIL_*` |

失敗しても登録作業は止めず、題名の手入力や表紙の手動指定に倒せます。

### 6-2. 内部 JSON（ログイン必須）

| 経路 | 用途 |
|------|------|
| `GET /admin/books/lookup` | 管理者 ISBN 検索 |
| `POST /admin/books/covers` | 表紙ファイル |
| `POST /covers/remember` | 一般。見えた表紙の保存（スロットルあり） |
| `GET /covers/{id}` | 自前表紙の表示 |

フロントの書籍検索画面は、ブラウザから Google Books を直接呼びます。

## 7. バッチ処理

キューワーカー前提のジョブ基盤は、本サーバーの日常運用では使いません。期限切れは **スケジュール（cron）** です。

| 処理 | 起動 | 内容 |
|------|------|------|
| `library:notify-overdue-slack` | 毎分（`Asia/Tokyo`） | 未通知の期限切れを Slack へ。重複送信しない（`slack_notified_at`） |
| `library:notify-overdue-slack --dry-run` | 手動 | 送信せず内容確認 |
| `library:notify-overdue-slack --sample` | 手動 | 実験メッセージ |
| `ImportCompanyBooks` | 手動 artisan | 蔵書取り込み用コマンド |

本サーバーではコンテナ内で毎分 `schedule:run` する（OS の cron は使わない。[AWSセットアップ](./AWSセットアップ.md)）。

定義は `routes/console.php`。運用の確認は [保守運用手順書 第5章](./保守運用手順書.md) です。

件数 0 では送りません。管理者アカウントへは本人 DM しません。
