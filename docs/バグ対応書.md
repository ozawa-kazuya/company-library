## 1. この資料の目的

本システムで **不具合（バグ）が発生した際** に、

- 利用者・管理者が **最初に試すこと**
- 開発担当が **調査・修正する手順**
- 再発防止の **記録の残し方**

を統一するための資料です。

---

## 2. 障害レベルの判断

| レベル | 目安 | 対応目標 | 例 |
|--------|------|---------|-----|
| **P1 重大** | 全員が利用不可 | 即時対応 | ログイン不可、DB 接続エラー、全画面真っ白 |
| **P2 高** | 主要機能が使えない | 当日中 | 貸出・返却が全員できない、管理者メニューが開けない |
| **P3 中** | 一部機能のみ | 数日以内 | 書影が表示されない、検索が効かない |
| **P4 低** | 表示崩れ・軽微 | 次回リリース | 文言誤り、スマホでのレイアウトずれ |

**エスカレーション:** P1・P2 は開発担当へ即連絡。利用者には「調査中」と状況を共有する。

---

## 3. 報告を受けたとき（一次対応）

利用者から「動かない」「エラーが出る」と連絡があった場合、**開発に渡す前** に以下を確認してください。

### 3-1. 基本チェックリスト

- [ ] **再現手順** をメモした（何をしたら起きるか）
- [ ] **誰のアカウント** か（社員番号・管理者／一般）
- [ ] **いつから** 起きているか（以前は動いていたか）
- [ ] **ブラウザ**（Chrome / Safari 等）と **端末**（PC / スマホ）
- [ ] **ネットワーク**（社内 Wi-Fi / 自宅 / テザリング）
- [ ] **画面のエラーメッセージ** をそのまま記録（スクショ推奨）
- [ ] **スーパーリロード** を試した（`Cmd + Shift + R` / `Ctrl + Shift + R`）
- [ ] **別ブラウザ** または **別端末** でも同じか確認した

### 3-2. 一次対応で試すこと（利用者・管理者）

| 症状 | まず試すこと |
|------|-------------|
| 画面が真っ白 | スーパーリロード → 再ログイン |
| ログインできない | 社員番号の大文字小文字、Caps Lock、パスワード再確認 |
| 返却できない | 社内 Wi-Fi 接続か確認（[マニュアル 第6章](./マニュアル.md#6-運用ルール)） |
| 借りられない | ISBN が台帳登録済みか、全冊貸出中でないか管理者に確認 |
| 管理メニューの色が消えた | スーパーリロード（キャッシュ古い可能性） |

### 3-3. 開発へエスカレーションするタイミング

以下に該当したら **開発担当へ引き継ぎ** してください。

- 上記一次対応でも解消しない
- 複数ユーザーで同時に発生
- データ消失・誤った貸出記録など **データ整合性** に関わる
- セキュリティ（不正ログイン、権限 bypass）の疑い

| 項目 | 記入例 |

| 一次対応の結果 | スーパーリロード済み、変わらず |

## 5. よくある事象と対処（クイックリファレンス）

入口は [よくあるトラブル.md](./よくあるトラブル.md) です。画面の文言の正は [マニュアル 第8章](./マニュアル.md) です。

### 5-1. 利用者向けエラー（仕様・運用）

[マニュアル](./マニュアル.md) のエラー一覧と同内容です。**バグではなく設定・運用** の場合が多いです。

| 現象 | 原因 | 対処 |
|------|------|------|
| 返却ボタンが押せない | 返却場所制限（社外 IP） | 社内 Wi-Fi に接続 |
| テザリングなのに返却できた | PC が localhost 経由、または Wi-Fi 残存 | `.env` の `RETURN_ALLOW_LOCALHOST` を確認 |
| この本はすべて貸出中 | 在庫ゼロ | 返却待ち、または管理者が在庫追加 |
| ISBN が見つからない | 未登録 | 管理者が資料登録 |
| 除名できない | 貸出中 | 先に返却 |

### 5-2. 技術的な既知事象（開発・運用）

| 現象 | 原因 | 対処 |
|------|------|------|
| **管理メニューの色が消える** | Tailwind が `menuItems.js` を未スキャン | `tailwind.config.js` に `./resources/js/**/*.js` があるか確認 → `npm run build` |
| **書影が表示されない** | OpenBD に表紙が無い | 版元ドットコム → Open Library → Google Books の順でフォールバック。それでも無ければ資料登録・全資料編集の「表紙画像を選ぶ」で設定。未設定ならグラデーション表示 |
| **書籍検索が動かない** | Google Books API URL 不正 | `BookSearch.jsx` の API エンドポイントを確認 |
| **1週間が2週間表示** | 日数計算の丸め | `duration_days` カラムと `loanDisplay.js` を確認 |
| **貸出期間が効かない** | `due_date` が保存されていない | `Loan` モデルの `$fillable` を確認 |
| **管理者が本棚に行く** | ログイン後リダイレクト | `BookController::index` の `isAdmin()` 分岐を確認 |
| **EMP-0001 で管理画面に行けない** | 社員番号の大文字小文字 | ログイン時の正規化・`isAdmin()` を確認 |
| **設定変更が反映されない** | 設定キャッシュ | `php artisan config:clear` |
| **PHPUnit が落ちる** | UserFactory に `user_code` なし | `database/factories/UserFactory.php` を確認 |

### 5-3. 「バグ」か「仕様」かの見分け方

```
利用者の報告
    │
    ├─ エラーメッセージが画面に出ている
    │       → マニュアルの「エラーメッセージと対処」を確認
    │       → 該当すれば仕様・運用で説明
    │
    ├─ 画面が真っ白・500 エラー
    │       → 技術障害（P1〜P2）として開発へ
    │
    └─ 「こうしてほしい」
            → 要望（機能改善）。バグ対応書ではなく要件として別管理
```

## 6. 開発担当者向け：調査手順

### 6-1. 環境確認

```bash
cd /path/to/company-library

# バージョン・状態
php -v
php artisan --version
git status
git log -3 --oneline

# 設定
php artisan config:show library.return_location   # 返却制限
grep RETURN_ .env

# テスト
php artisan test
```

### 6-2. ログの確認


| ログ | 場所 | 用途 |
|------|------|------|
| Laravel アプリログ | CloudWatch Logs（`LOG_CHANNEL=stderr`） | 例外・SQL エラー |
| 入口 | ALB のアクセスログ | 502 / 504 等 |

```bash
# CloudWatch Logs で直近の ERROR を見る（クラスタ名・ロググループは CDK の出力）
```

### 6-3. 再現の手順

1. 報告の **再現手順** をそのまま実行
2. **同じユーザー権限**（admin / user）で試す
3. **DB 状態** を確認（該当 book / loan / user レコード）
4. ブラウザ **開発者ツール → Network** で 4xx / 5xx を確認
5. **Console** で JavaScript エラーを確認

### 6-4. 頻出調査ポイント（機能別）

| 機能 | 確認ファイル |
|------|-------------|
| ログイン | `LoginRequest.php`, `AuthenticatedSessionController.php` |
| 貸出 | `BookController::borrowExec`, `Book::findAvailableCopyByIsbn` |
| 返却 | `EnsureReturnLocation` ミドルウェア, `ReturnLocationGuard.php` |
| 資料登録 | `BookController::adminBookStore`, `adminBookLookup` |
| フロント表示 | `public/build/` の有無, `public/hot` の有無 |
| スタイル | `tailwind.config.js` の `content` パス |

### 6-5. DB 確認

```bash
php artisan tinker
```

```php
// 例：貸出中の確認
\App\Models\Loan::with('book', 'user')->whereNull('returned_at')->get();

// 例：同一 ISBN の在庫
\App\Models\Book::where('isbn', '9784815608774')->get(['id', 'copy_number', 'title']);
```

本サーバーでは ECS Exec またはワンショットタスクから実行する（[AWSセットアップ](./AWSセットアップ.md)）。

## 7. 修正・リリース手順

### 7-1. 修正の流れ

```
1. 原因特定
2. 最小限の修正（関連コードのみ）
3. php artisan test で回帰確認
4. フロント変更時は npm run build
5. ステージング／本番へ反映
6. 報告者に確認依頼
7. 対応記録を残す（第9章）
8. 必要ならマニュアル・説明資料を更新
```

### 7-2. リリース前チェックリスト

- [ ] `php artisan test` がすべて成功
- [ ] 修正対象画面をブラウザで目視確認
- [ ] 管理者・一般社員の両方で主要フロー確認（ログイン → 借りる → 返却）
- [ ] フロント変更時：`npm run build` 済み、`public/hot` が本番に残っていない
- [ ] `.env` の変更がある場合：`config:clear` 手順を運用メモに記載
- [ ] マイグレーションがある場合：バックアップ後に `php artisan migrate`

### 7-3. 本サーバーへの反映

イメージをビルドしてタスクを更新する（[AWSセットアップ](./AWSセットアップ.md)）。Linux 1 台への `git pull` は本サーバーの手順ではない。

## 8. 復旧・ロールバック

### 8-1. サービス全体が停止している場合

1. ALB・Fargate・RDS の状態確認
2. CloudWatch Logs で直近の例外を確認
3. Secrets Manager の DB 接続を確認
4. 直前のデプロイを **ロールバック**（下記）

### 8-2. Git によるロールバック（参考）

```bash
# 直前のコミットに戻す（要・チーム合意）
git log -5 --oneline
git revert <問題のコミットハッシュ>
# または
git checkout <正常だったタグまたはコミット> -- .
```

> **注意:** DB マイグレーションを戻す場合は `migrate:rollback` の影響範囲を必ず確認してください。

### 8-3. データ復旧

| 状況 | 対応 |
|------|------|
| 誤返却 | `loans` テーブルの `returned_at` を NULL に戻す（要・管理者判断・バックアップ前提） |
| 誤除名 | バックアップから `users` を復元（[マニュアル](./マニュアル.md)） |
| DB 破損 | [データバックアップリストア](./データバックアップリストア.md) |

本番 MySQL の全件復元は [データバックアップリストア](./データバックアップリストア.md) です。

**原則:** 本番 DB の直接編集は **バックアップ取得後** に限る。可能なら開発環境で手順を試してから実施。
