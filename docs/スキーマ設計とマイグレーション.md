# 社内図書貸出管理システム スキーマ設計とマイグレーション

| 項目 | 内容 |
|------|------|
| 対象 | 開発担当・運用担当 |
| 最終更新 | 2026年9月 |

**Laravel のマイグレーションを使う。** 別ツール（Flyway、Liquibase、Prisma、Atlas など）は入れていない。スキーマの正は `database/migrations/` の PHP ファイルである。

カラムの詳細と ER 図は [基本設計書 第5章](./基本設計書.md)。エンジンの種類は [データベース種類.md](./データベース種類.md)。

---

## 1. スキーマ設計の概要

リレーショナルモデル。業務の中心は次の 4 テーブル。

```
users 1 ──< loans >── 1 books
                         │
                         └─（論理）cover_images
                            books.cover が /covers/{uuid} のとき
                            DB の外部キーは無い
```

| テーブル | 役割 | ポイント |
|----------|------|----------|
| `users` | 利用者 | `user_code`（社員番号）と `email` は UNIQUE。`role` は `user` / `admin` |
| `books` | 書籍（**冊**単位） | 同一 ISBN は複数行。`isbn` は検索用 INDEX（UNIQUE ではない）。`copy_number` で冊を区別 |
| `loans` | 貸出履歴 | `user_id` / `book_id` は FK CASCADE。未返却は `returned_at IS NULL`。同時に 1 冊 1 件はアプリ層で保証 |
| `cover_images` | 自前表紙 | PK は UUID。本体は BLOB（MySQL では MEDIUMBLOB） |

貸出中かどうかの正は `loans.returned_at`。`books.status` は補助。

ほかに Laravel 標準の `sessions`、`password_reset_tokens`、`cache`、`jobs` などがある（セッション・キャッシュ・キュー用）。

## 2. 管理方法（マイグレーションを使う）

| 項目 | 内容 |
|------|------|
| ツール | **使う。** Laravel 組み込み（`php artisan migrate`） |
| 定義の場所 | `database/migrations/*.php` |
| 適用履歴 | DB の `migrations` テーブル（ファイル名を記録） |
| ORM | Eloquent（モデルは `app/Models/`。[SQLとORM方針](./SQLとORM方針.md)） |
| スキーマダンプ | **使わない**（`schema:dump` の SQL はリポジトリに無い） |

適用は未実行のファイルだけ走る。同じファイルを二度は実行しない。

| 環境 | いつ走らせるか |
|------|----------------|
| 本サーバー | イメージ更新のあと `php artisan migrate --force`（[AWSセットアップ](./AWSセットアップ.md)） |
| 自動テスト | PHPUnit の `RefreshDatabase` |

データ投入（シーダー）はスキーマとは別。`php artisan db:seed` はテーブル作成後に行う。

## 3. 使わないもの

| 方法 | 使用 |
|------|------|
| Flyway / Liquibase / Atlas | 使わない |
| Prisma / TypeORM など別 ORM の migrate | 使わない |
| 本番で phpMyAdmin や `ALTER TABLE` を手打ちしてスキーマを変える | しない（定義と DB がずれる） |
| `php artisan migrate:fresh` / `db:wipe` を本サーバーで | **禁止**（全テーブル削除） |
| 既存のマイグレーション PHP を後から書き換えて本番に当てる | しない（未適用環境と矛盾する） |

本番の戻しは `migrate:rollback` より、バックアップからの復元を優先する（[データバックアップリストア](./データバックアップリストア.md)）。

---

## 4. 変更の手順

1. バックアップ（本サーバーなら [データバックアップリストア](./データバックアップリストア.md)）
2. ファイルを追加する（既存ファイルは編集しない）

```bash
php artisan make:migration add_something_to_books_table
```

3. `up()` に変更、`down()` に戻しを書く
4. `php artisan migrate` と `php artisan test`
5. Git に載せて本サーバーで `php artisan migrate --force`

未適用の一覧:

```bash
php artisan migrate:status
```

カラム変更の一部（`->change()`）は MySQL 向け。本サーバーの RDS で確認する。

データ直しだけのマイグレーションもある（例: カテゴリ名の正規化）。テーブル構造が変わらなくても、適用履歴は同じ `migrations` テーブルに残る。
