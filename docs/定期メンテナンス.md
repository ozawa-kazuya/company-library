# 社内図書貸出管理システム 定期メンテナンスのスケジュール

| 項目 | 内容 |
|------|------|
| 対象 | 運用担当・開発担当・管理者 |
| 最終更新 | 2026年9月 |
| 対象環境 | **本サーバー ＝ AWS**（定義あり・未デプロイ） |

**いつ何をするかの一覧である。** コマンドと画面操作の手順は [保守運用手順書](./保守運用手順書.md)。ダンプは [データバックアップリストア](./データバックアップリストア.md)。24時間必須ではない（[基本設計書 10-2](./基本設計書.md)）。計画停止は社内業務時間外を推奨する。

カレンダー製品（PagerDuty、AWS Maintenance Window 等）は使わない。人の点検は下表どおり手作業である。

---

## 1. 自動（人が毎回やらなくてよい）

| 頻度 | 内容 | 備考 |
|------|------|------|
| **毎分** | `php artisan schedule:run` → 期限切れ Slack | `routes/console.php`。タイムゾーン `Asia/Tokyo`。OS の cron が前提（[保守運用手順書 第5章](./保守運用手順書.md)） |
| **毎日** | MySQL `mysqldump` → gzip。可能なら別筐体へコピー | 1 回以上。cron 化。[障害予防の3点](./障害予防の3点.md) |

Slack が来ないときは cron 未登録を疑う。バッチは貸出期限の通知だけである。OS や PHP のセキュリティパッチは、サーバー担当の社内ルールに従う（本アプリは日程を決めていない）。

---

## 2. 人がやる点検

| 頻度 | 担当 | 作業 | 手順 |
|------|------|------|------|
| **毎日（業務開始時）** | 管理者 | Slack または管理画面の期限切れ件数 | [マニュアル](./マニュアル.md) |
| **毎日** | 運用 | ログイン画面が開くこと。任意で `/up` | [保守運用手順書 第4章](./保守運用手順書.md) |
| **毎日** | 運用 | コンテナ内の毎分 `schedule:run` が動いていること | 同 第5章 |
| **毎週** | 運用 | ディスク容量（`df -h`） | [保守運用手順書 第9章](./保守運用手順書.md) |
| **毎週（推奨）** | 運用 | 直近ダンプをテスト用 DB へ戻せるか | [データバックアップリストア](./データバックアップリストア.md) |
| **毎月** | 運用 | CloudWatch のログ量（保持 3 日の定義） | 同 第9章。[ログ管理](./ログ管理.md) |

延長機能は無い。期限切れは本人へ返却を依頼する。管理画面から代理返却はできない。

---

## 3. 随時・イベント時

| きっかけ | 作業 | 手順 |
|----------|------|------|
| 新着資料・在庫 | 登録 / Excel 取り込み | [マニュアル](./マニュアル.md) |
| 入社 | 利用者登録（最大 5 名） | 同 |
| 退職・異動 | 貸出中がないことを確認して除名（社内異動のみなら除名しない） | [マニュアル](./マニュアル.md) |
| アプリ改修 | イメージ更新 / migrate。資料もコードに合わせる | [AWSセットアップ](./AWSセットアップ.md)。[ドキュメント管理](./ドキュメント管理.md) |
| オフィス移転・回線変更 | 場所制限の CIDR | 同 第7章 |
| Slack ワークスペース変更 | Webhook / Bot Token | 同 第5章 |
| migrate・DB 復元・再起動 | 計画停止の連絡 | 同 第11章 |

年度末の棚卸・集計機能は未実装である。必要なときは管理画面の検索と DB バックアップから別途集計する。
