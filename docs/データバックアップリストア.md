# 社内図書貸出管理システム データバックアップ・リストア手順

| 項目 | 内容 |
|------|------|
| 対象 | 運用担当・開発担当 |
| 最終更新 | 2026年9月 |
| 対象環境 | **本サーバー**（RDS MySQL） |

業務データの正は **MySQL のダンプ** です。専用のバックアップ製品（Spatie Laravel Backup など）は使いません。手順の位置づけは [保守運用手順書](./保守運用手順書.md)。頻度は [定期メンテナンス](./定期メンテナンス.md) です。

## 1. 何を残すか

| 対象 | 要否 | 方法 |
|------|------|------|
| 利用者・蔵書・貸出・表紙バイナリ | **必須** | `mysqldump`（`users` / `books` / `loans` / `cover_images` ほか全テーブル） |
| `.env` | 推奨 | ファイルコピー。権限 `600` |
| アプリコード | Git | ダンプに含めない |
| `vendor/` `node_modules/` | 不要 | `composer` / `npm` で再構築 |
| `storage/logs` | 任意 | 障害調査用。業務復元には不要 |

表紙本体は `cover_images.data`（MySQL では MEDIUMBLOB）に入っています。ディスク上の別ストレージにはありません。DB を戻せば表紙も戻ります。ダンプは表紙の分だけ大きくなります。

エンジンの種類は [データベース種類.md](./データベース種類.md)。テーブル構造は [スキーマ設計とマイグレーション.md](./スキーマ設計とマイグレーション.md)。

## 2. バックアップ（本サーバー）

毎日 1 回以上。アプリ更新・migrate・DB の手編集の **直前** にも取る。

保存先と保持日数はサーバーの運用ルールに合わせます。例（7 日保持）:

```bash
BACKUP_DIR=/var/backups/company-library
mkdir -p "$BACKUP_DIR"
chmod 700 "$BACKUP_DIR"
STAMP=$(date +%Y%m%d-%H%M)

mysqldump --single-transaction --default-character-set=utf8mb4 \
  -uアプリユーザー -p データベース名 \
  | gzip > "$BACKUP_DIR/library-${STAMP}.sql.gz"

chmod 600 "$BACKUP_DIR/library-${STAMP}.sql.gz"

cp /path/to/company-library/.env "$BACKUP_DIR/env-${STAMP}"
chmod 600 "$BACKUP_DIR/env-${STAMP}"

find "$BACKUP_DIR" -name 'library-*.sql.gz' -mtime +7 -delete
find "$BACKUP_DIR" -name 'env-*' -mtime +7 -delete
```

| 注意 | 内容 |
|------|------|
| パスワード | コマンド履歴に残さない。`~/.my.cnf`（権限 `600`）か対話の `-p` |
| cron | アプリ接続ユーザーとは別の、ダンプ専用ユーザーを推奨 |
| 確認 | ファイルサイズが 0 でないこと。週に 1 回、テスト用 DB へ戻せるか試すと安心 |
| 別筐体 | 同じディスクだけだとマシンごと消えたときに戻らない。NAS・別サーバーへコピーする（[障害予防の3点](./障害予防の3点.md)） |

`--single-transaction` は InnoDB 向けです。取得中も読み取りは続きますが、復元作業中は貸出を止めます。

## 3. リストア（本サーバー）

ダンプを流すと **その時点の全テーブルで上書き** されます。復元直前にもう一度ダンプを取り、戻すファイル名を記録します。

1. 利用者へ開始時刻を伝える（[保守運用手順書 第11章](./保守運用手順書.md)）
2. 新規の貸出・返却を止める

```bash
cd /path/to/company-library
php artisan down
```

Web サーバーを止めてもよいです。

3. 戻す

```bash
gunzip -c /var/backups/company-library/library-YYYYMMDD-HHMM.sql.gz \
  | mysql --default-character-set=utf8mb4 -uアプリユーザー -p データベース名
```

4. 再開と確認

```bash
php artisan config:clear
php artisan up
```

ログイン → 本棚または管理メニュー → 貸出中・表紙が付いている本を目視します。

| 状況 | そのあと |
|------|----------|
| ダンプ時点のコードと同じ | migrate は不要（`migrations` テーブルもダンプに含まれる） |
| ダンプより新しいコードを動かしている | 不足分だけ `php artisan migrate --force`（[スキーマ設計とマイグレーション](./スキーマ設計とマイグレーション.md)） |
| `.env` も壊れている | バックアップの `env-*` を戻し、`chmod 600` のうえ `config:clear` |

`migrate:fresh` は使いません。誤ったダンプを流した場合は、復元直前に取ったダンプへ戻します。

## 4. 行単位の復旧（全件リストアしない）

全 DB を戻すと、その後の正しい貸出も消えます。件数が少ないときはバックアップ取得後に、管理者判断で行だけ直します。

| 状況 | 対応 |
|------|------|
| 誤返却 | `loans.returned_at` を NULL に戻す（同時に未返却が 2 件にならないこと） |
| 誤除名 | 可能なら `users` を再登録。履歴まで必要なら該当時点のダンプから抜くか全件リストア |

本番の直接 SQL はバックアップ後に限ります。可能ならコピーした DB で先に試します。記録は [バグ対応書 8-3](./バグ対応書.md) です。
