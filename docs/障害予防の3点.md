# 社内図書貸出管理システム 障害予防の3点

| 項目 | 内容 |
|------|------|
| 対象 | 運用担当・開発担当 |
| 最終更新 | 2026年9月 |
| 対象環境 | **本サーバー ＝ AWS**（定義あり・未デプロイ） |

**サーバーが壊れても、データが残っていればすぐ組み立て直せる。** アプリの新機能ではない。先に次の3つを整える。コマンドの正は既存資料。このページは地図である。

---

## 原則

蔵書・貸出履歴・利用者は MySQL にある。コードは Git。壊れたマシンの上にだけ dump があると、マシンごと消えたときに復元できない。

24時間有人監視は必須ではない（[基本設計書 10-2](./基本設計書.md)）。人が来る前に落ちたことに気づくには、**外からの死活** が要る。直し方を一人だけが知っている状態にしない。

---

## 1. 自動バックアップ（最優先）

前日または先週の dump があれば、サーバーを作り直して戻せる。対象は図書台帳と貸出履歴（`users` / `books` / `loans` / `cover_images` ほか全テーブル）。

| 項目 | 本システム |
|------|------------|
| 方法 | 毎日 1 回以上の `mysqldump` → gzip。[データバックアップリストア](./データバックアップリストア.md) |
| 起動 | OS の cron。アプリの `schedule:run` には入れてない |
| 同じディスクだけ | 足りない。NAS・別サーバー・社内ファイルサーバなど **別筐体** にもコピーする |
| 確認 | サイズ 0 でないこと。週1 はテスト用 DB へ戻せるか |

手順・保持日数の例はデータバックアップリストア第2章。復元は同第3章と [保守運用手順書 第11章](./保守運用手順書.md)。

まだ cron が無い本サーバーでは、**今日入れる。** 手作業の dump だけにしない。

---

## 2. 死活の外部監視

利用者が「開かない」と言う前に、運用が落ちたことを知る。

| 項目 | 本システム |
|------|------------|
| アプリ側 | `GET /up` が 200 なら Laravel は応答している（[保守運用手順書 第4章](./保守運用手順書.md)） |
| 人が見る | 毎日のログイン画面確認（[定期メンテナンス](./定期メンテナンス.md)） |
| 外からの自動通知 | **未導入。** New Relic / Prometheus / CloudWatch アラームも無い（[パフォーマンスモニタリング](./パフォーマンスモニタリング.md)） |

入れるなら、社外（または別網）から `https://本サーバー/up` を定期 GET し、失敗したら Slack 等へ「落ちている」。無料枠の例として Uptime Robot がある。アカウントと監視 URL はこのリポジトリに無い。運用が契約して登録する。

`/up` は DB や OpenBD の死活までは見ない。ログイン画面も開けないときだけ先に分かる。

期限切れ Slack（毎分バッチ）は **貸出超過の通知** であり、サーバー死活ではない。

---

## 3. 手順書（属人化しない）

1枚でもよい。共有場所に置く。正本は Git の `docs/`（[ドキュメント管理](./ドキュメント管理.md)）。Notion の引き継ぎはコピーである。

| 起きること | 見る資料 |
|------------|----------|
| dump から戻す | [データバックアップリストア](./データバックアップリストア.md) |
| いつ点検するか | [定期メンテナンス](./定期メンテナンス.md) |
| 画面操作 | [マニュアル](./マニュアル.md)。案内は [運用マニュアル](./運用マニュアル.md) |

Wiki だけを正にしない。直したら `docs/` を直す。

## いまの状態

| 点 | アプリに入っているか | 本サーバーでやること |
|----|----------------------|----------------------|
| 1. 自動バックアップ | 手順とコマンドはある。cron は OS 側 | dump の cron と **別筐体へのコピー** |
| 2. 外部死活 | `/up` のみ。Uptime Robot 等は未導入 | 外から `/up` を見る仕組みを契約・登録 |
| 3. 手順書 | `docs/` と引き継ぎ Notion | 実ホスト名・再起動サービス名を運用が追記 |
