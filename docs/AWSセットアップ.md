## まとめ

図書管理アプリの **本サーバーは AWS** である。定義はある。まだデプロイしていない。課金は始まっていない。アプリのコードは 1 本。**夜間停止はしない。24 時間付けっぱなし。**

**配置**

```
社員ブラウザ（HTTPS）
  → ALB（証明書は ACM。HTTP は HTTPS へ転送）
    → ECS Fargate（Nginx + PHP。ARM 0.25 vCPU / 512MB）
      → RDS MySQL（db.t4g.micro・1 AZ。外から 3306 は開かない）
```

秘密は Secrets Manager、ログは CloudWatch（3 日）、配置は ECR、期限切れ Slack はコンテナ内の毎分。NAT・Aurora・Lambda・SES・WAF は使わない。HTTPS には公開ドメインが必要（`infra/cdk.json` の `domainName`）。

**技術スタック** … PHP 8.3 / Laravel 13 / React 18 / Inertia.js / Tailwind / Vite。認証はセッション。公開 REST API は無い。本サーバーの DB は RDS MySQL。

**料金** … 東京・24 時間で月 **約 8,000〜11,000 円**（税別）。AWS が高い理由は、入口と DB を分けて常時置く代である。

**AWS のメリット** … 安さではない。役割が分かれる、DB を外に出さない、OS パッチは AWS 側、秘密をファイルに置かない、CDK で作り直せる／止められる。SSH しない。ほぼ放置できる。RDS は 1 AZ なので、その AZ が止まると DB も止まる。

**攻撃** … 入口は探される。探されることと入られることは別。外から届くのは ALB だけ。DB と秘密は外に出していない。ログインは HTTPS。WAF は無い。

**運用** … 社員から見える画面は同じ。AWS は箱を分けてイメージ更新。SSH しない。

**なぜ ECR なのか** … Fargate がイメージを取る倉庫。同じ AWS の中で一番素直。EC2 が無いので `git pull` する OS が無い。Docker Hub や S3 には置かない。

**EC2 で安くなるか** … Fargate だけ EC2 に差し替えても、高いのは ALB と RDS なのでほとんど下がらない。EC2 1 台に全部載せる形は **採らない。**

**ALB と RDS の代用** … 安い代用は Nginx と MySQL を自分の台に置くこと。1 台にまとめる形なので **採らない。** マネージドのまま同じ役割で安い箱は、この規模ではない。

**このアプリの規模** … 社内の本棚。同時に使う想定は数十人。蔵書はいま約 80 冊。外向けサービスではない。アクセスは少ない。だから ALB と RDS の「置いてある代」が先に効く。

**一番いいのは** … **AWS の 24 時間（Fargate）**。EC2 1 台は無し。夜間停止はしない。

## 0. 環境回りの説明（社内向け）


### 説明文（読み上げ用）

社内図書の本サーバーは AWS です。Linux を 1 台借りて、その中に Web も PHP も MySQL も全部載せる構成ではありません。入口、計算、データベース、秘密情報、ログを、それぞれ専用のサービスに分けます。アプリのコードは今までどおり 1 本です。変わるのは箱の分け方だけです。いまリポジトリにあるのはその定義で、まだデプロイはしていません。課金もまだ始まっていません。

社員がブラウザで開く先は ALB です。ロードバランサーで、配下のコンテナへリクエストを振ります。Laravel 本体は ECS Fargate で動かします。中身は Nginx と PHP-FPM のコンテナです。EC2 の OS には入りません。データは RDS MySQL（db.t4g.micro、1 AZ）です。アプリのコンテナからしか繋がりません。パスワードと APP_KEY は Secrets Manager に置き、コンテナのディスクには書きません。ログは CloudWatch Logs です。コンテナは消えるので、サーバー上の laravel.log には残しません。期限切れの Slack は、今の cron と同じく毎分動かしますが、置き場はコンテナの中です。Lambda や EventBridge の毎分起動は使いません。アプリの配置物は ECR のイメージです。git pull してサーバー上で composer する運用ではありません。

ネットワークは VPC で 2 層にします。パブリック側に ALB と Fargate を置きます。社員のブラウザが見るのは ALB だけです。書誌 API と Slack へ出るため、Fargate にパブリック IP を付けます。NAT Gateway は置きません。月額を抑えるためです。RDS はインターネットに出ない分離サブネットに置きます。外から 3306 は開けません。誰が誰のポートに来てよいかはセキュリティグループで決めます。ALB は 443（HTTPS）と、80 から 443 への転送です。アプリ（Fargate）は ALB から 80、DB はアプリから 3306 です。証明書は ACM です。公開できるドメインが必要です。

使わないものを先に言います。Lambda は PHP の常駐向きではないので使いません。メールは社内または契約の SMTP のままです。SES は使いません。表紙はデータベースの BLOB のままです。S3 には移しません。WAF も今回は入れません。Aurora も使いません（常時 0.5 ACU でも月額が先に効くため）。

リージョンは東京です。**最小構成**で、Fargate は ARM の 0.25 vCPU・メモリ 512MB を 1 つ、RDS は db.t4g.micro の 1 台です。これより小さい Fargate と RDS の組み合わせは、この形では取れません。**夜間停止はしません。24 時間付けっぱなしです。** 月額の目安は 約 8,000 円から 11,000 円です。その代わり、OS のパッチと MySQL の箱は AWS 側のマネージドになります。SSH しません。ほぼ放置できます。AZ 障害時は DB が止まります。業務データは本サーバーの RDS だけが正です。

### 役割の対応


| 役割         | 本サーバー（AWS）                                   |
| ---------- | -------------------------------------------- |
| 社員が開く URL  | **ALB**（HTTPS。80 は 443 へ転送）                  |
| Web + PHP  | **ECS Fargate**（コンテナ。EC2 の OS は自分で見ない）       |
| データ        | **RDS MySQL**（db.t4g.micro・1 AZ。アプリからしか届かない） |
| 秘密         | **Secrets Manager**（パスワードをファイルに置かない）         |
| アプリログ      | **CloudWatch Logs**（コンテナは消えるのでファイルに残さない）     |
| 期限切れ Slack | コンテナ内の毎分 `schedule:run`（EventBridge では起動しない） |
| 配置物        | **ECR**（イメージ）                                |


### なぜ ECR なのか

Fargate がイメージを取る場所として、同じ AWS の中で一番素直だからである。仮想マシンが無いので、`git pull` するディスクが無い。動かす単位がコンテナなので、倉庫が要る。それが ECR である。

CDK の `cdk deploy` がイメージをビルドして ECR に載せ、Fargate が IAM で取り出す。別のパスワードをタスクに埋めなくて済む。リージョンも東京で揃うので、外に出してから戻す必要が無い。イメージは非公開である。


| 代わり               | 使わない理由                            |
| ----------------- | --------------------------------- |
| サーバー上の `git pull` | EC2 が無い。入る OS が無い                 |
| Docker Hub        | 社外に置く。認証とレート制限が足る。Fargate から見て遠回り |
| S3 に zip          | コンテナの置き場ではない。Fargate はレジストリから取る   |


金曜の言い方: 「箱がコンテナなので倉庫が要る。同じ AWS なら ECR。git pull するサーバーは持たない。」

ネットワーク（VPC）は 2 層にする。

- **パブリック** … ALB と Fargate。社員のブラウザは ALB だけ見る。Fargate にパブリック IP を付け、国立国会図書館・OpenBD・Slack へ出る（NAT Gateway は置かない。月額を抑える）
- **分離（インターネットに出ない）** … RDS。外から 3306 は開けない。Fargate のセキュリティグループからのみ

セキュリティグループは「誰が誰のポートに来てよいか」だけ決める。ALB は 443 と 80（転送）、アプリは ALB から 80、DB はアプリから 3306。

使わないもの（今回）: **Lambda**、**Aurora**、**EventBridge の毎分タスク**、**SES**、**S3 表紙**、WAF。

本サーバー（AWS）は「入口・計算・DB・秘密・ログ」を分ける。社内図書の規模では **月 約 8,000〜11,000 円**。その代わり、OS パッチや MySQL の箱は AWS 側のマネージドになる。RDS は 1 AZ なので、その AZ が止まると DB も止まる。

リージョンは **東京（ap-northeast-1）**。**最小構成**（Fargate ARM 0.25 vCPU / 512MB を 1 つ、RDS db.t4g.micro）。

## 1. 構成

リージョンは **ap-northeast-1（東京）**。**最小構成**（Fargate ARM 0.25 vCPU / 512MB を 1 タスク、RDS MySQL db.t4g.micro・1 AZ）。NAT Gateway は置かない。Aurora は使わない。


| 役割         | 本サーバー（AWS）                                         |
| ---------- | -------------------------------------------------- |
| 公開 URL     | ALB（HTTPS。HTTP は転送）                                |
| Web + PHP  | ECS Fargate（Nginx + PHP-FPM、ARM 0.25 vCPU / 512MB） |
| 期限切れ Slack | コンテナ内の毎分 `schedule:run`                            |
| DB         | RDS MySQL（db.t4g.micro、1 AZ）                       |
| 秘密         | Secrets Manager                                    |
| アプリログ      | CloudWatch Logs                                    |
| 配置物        | ECR                                                |


使わない（今回）: Lambda、Aurora、EventBridge 起動の毎分タスク、SES、S3 表紙、WAF、NAT Gateway。

```
社員ブラウザ
  → ALB（HTTPS:443。HTTP:80 は転送）
    → Fargate（ARM。コンテナ内は HTTP。書誌 API・Slack へ出る）
      → RDS MySQL（分離サブネット。インターネットに出さない）
```

月額の目安（24 時間・東京、未デプロイのため実課金は無し）: **約 8,000〜11,000 円**（税別・為替で上下する）。NAT を足すと約 +5,000〜8,000 円。


| 項目                                 | いまの定義                                      | 月額の目安                               |
| ---------------------------------- | ------------------------------------------ | ----------------------------------- |
| RDS MySQL                          | db.t4g.micro・1 AZ・20GB                     | **約 2,800〜3,500 円**                 |
| ECS Fargate                        | ARM 0.25 vCPU / 512MB を 1 タスク（Fargate の下限） | 約 1,350 円                           |
| ALB                                | HTTPS:443 + HTTP→HTTPS。証明書は ACM（無料）        | 時間課金は HTTP だけとほぼ同じ                  |
| パブリック IPv4                         | Fargate と ALB                              | 約 1,000〜1,700 円                     |
| Secrets Manager / CloudWatch / ECR | 秘密 2 つ、ログ 3 日                              | 数百〜1,000 円                          |
| NAT Gateway                        | **置かない**                                   | 足すと +約 5,000〜8,000 円                |
| Aurora Serverless v2               | **使わない**                                   | 0.5 ACU 常時だと約 8,000〜9,000 円になるため外した |


課金はデプロイした瞬間から始まる。壊して止めるのは `cdk destroy`。1 AZ の RDS は、その AZ 障害で止まる。

### 費用を抑える方法

**いまの定義で既にやっていること**


| やること                                             | 効き方                                                    |
| ------------------------------------------------ | ------------------------------------------------------ |
| Aurora を使わない                                     | 常時 0.5 ACU だと月 約 8,000〜9,000 円。RDS micro にすると約 3,000 円 |
| NAT Gateway を置かない                                | 足すと月 +約 5,000〜8,000 円                                  |
| Fargate を ARM の下限（0.25 vCPU / 512MB）にする          | x86 の 0.5 vCPU / 1GB より安い                              |
| RDS を 1 AZ・db.t4g.micro                          | Multi-AZ や Aurora にしない                                 |
| Lambda / EventBridge 毎分 / SES / WAF / S3 表紙を使わない | 常時箱が増えない                                               |
| ログを 3 日で消す                                       | CloudWatch の取り込み・保管を小さくする                              |
| 未使用なら `cdk destroy`                              | 止めた月はほぼ 0 円。残すと ALB と RDS が 24 時間課金される                 |


この形のままこれ以上箱を小さくはできない。Fargate と RDS はすでに下限、ALB を外すと URL が安定しない。

**まだやっていない・選択肢**


| 方法                                          | 目安                    | 代償                       |
| ------------------------------------------- | --------------------- | ------------------------ |
| ALB を外してタスクのパブリック IP で公開                    | 月 約 −2,600〜3,500 円    | タスクが置き換わると URL が変わる      |
| 1 年予約（RDS Reserved / Compute Savings Plans） | 常時使うなら 2〜4 割安くなることがある | 契約期間。使わなくても払う            |
| Fargate だけ EC2 に差し替える（ALB + RDS は残す）        | 数百円下がる程度              | OS パッチと SSH が戻る。**採らない** |
| EC2 1 台に全部載せる                               | 約 3,000〜5,000 円       | 1 台にまとめる形。**採らない**       |
| Lightsail 1 台                                | 数千円台                  | 1 台にまとめる形。**採らない**       |
| デプロイしない（いまの状態）                              | **0 円**               | 社員は本サーバーを使えない            |


社内図書はアクセスが少ない。箱を 24 時間置き続けると、ALB と RDS の「置いてある代」が先に効く。EC2 1 台は **採らない。** 費用を止めるなら **デプロイしない**（または後から `cdk destroy`）。

### 値段を抑えるなら EC2 では

「値段を抑えるなら EC2 でいい」は、1 台に全部載せるなら料金だけ正しい。**採らない。** Fargate を EC2 に差し替えるだけなら、ほとんど安くならない。

いまの月額で高いのは計算（Fargate 約 1,350 円）ではなく、**ALB と RDS を常時置く代**である。計算だけ EC2（例: t4g.micro）にしても、入口と DB は残る。下がるのは数百円。その代わり、OS に入り、パッチを当て、ディスクを見る仕事が戻る。SSH しない、という今の取り方を捨てることになる。


| 取り方                        | 月額の目安            | 判断        |
| -------------------------- | ---------------- | --------- |
| いまの定義（ALB + Fargate + RDS） | 約 8,000〜11,000 円 | **これで行く** |
| Fargate だけ EC2 に差し替え       | ほぼ同じ（数百円安）       | 採らない      |
| EC2 1 台に Web + PHP + MySQL | 約 3,000〜5,000 円  | **採らない**  |


金曜の言い方: 「EC2 1 台は無し。Fargate だけ EC2 にしても ALB と RDS が残るのでほとんど安くならない。」

### ALB と RDS の代用

ある。ただし **安い代用は、役割を分けることをやめる** ことである。1 台にまとめる形なので **採らない。** マネージドのまま「同じ仕事で安い箱」は、社内図書の規模ではない。

**ALB がやっていること** … 社員が見る URL を固定する。HTTPS を終端する（証明書は ACM）。HTTP を HTTPS へ転送する。死んだコンテナには振らない。


| 代用                          | 月額               | 失うもの                                      |
| --------------------------- | ---------------- | ----------------------------------------- |
| ALB を外して Fargate の公開 IP 直結  | 約 −2,600〜3,500 円 | タスクが置き換わるたびに URL が変わる。ACM を IP に直接は付けられない |
| CloudFront                  | 安くならないことが多い      | オリジンがまた要る。IP が変わる Fargate の前に置くと、結局 ALB が残る |
| NLB                         | 同額クラス            | HTTPS の転送は ALB 向き。安くならない                  |
| 自分の台の Nginx + Let's Encrypt | ALB 代は消える        | OS に入る。1 台にまとめる形。**採らない**                |


**RDS がやっていること** … コンテナが消えてもデータを残す。外から 3306 を開けない。自動バックアップ。MySQL の箱のパッチは AWS 側。


| 代用              | 月額                   | 失うもの                        |
| --------------- | -------------------- | --------------------------- |
| Fargate の中に MySQL | 計算は下がる               | **使えない。** コンテナが死ぬとデータも消える   |
| 同じ台の MySQL（EC2） | RDS 代が消える            | 1 台にまとめる形。**採らない**          |
| MySQL だけ別の EC2  | RDS より数百〜千円安くなることがある | OS と MySQL の手入れが戻る。箱はまだ 2 つ |
| 本サーバーも SQLite   | RDS 代は消える            | 同時書き込みとバックアップが弱い。開発用のまま     |
| Aurora          | **高い**               | 使わない                        |


ALB と RDS を両方外して安くするなら、残るのは **1 台に Nginx + PHP + MySQL** である。その形は **採らない。**

金曜の言い方: 「代用はある。安い代用は 1 台にまとめること。採らない。マネージドのまま同じ役割で安い箱は、この規模ではない。」

### このアプリの規模

社内の技術書・ビジネス書を、紙や Excel の代わりにブラウザで貸すアプリである。EC サイトでも、社外向けサービスでもない。ログインした社員だけが使う。公開 REST API は無い。借りる・返すのはオフィスのネットワークからの想定である。


| 項目     | いま分かっている規模                              |
| ------ | --------------------------------------- |
| 用途     | 社内図書の貸出・返却・在庫                           |
| 同時に使う人 | 設計上 **〜50 名**（[基本設計書 10-1](./基本設計書.md)） |
| アカウント  | 1 人 1 件。社員番号は数字 3 桁。登録は最大 5 名ずつ         |
| 蔵書     | 取り込み用データは **約 80 冊**（種 77・冊 79）         |
| アクセス   | 業務時間に本棚を見て借りる／返す。常時大量アクセスは無い            |
| 画面     | 3 秒以内（社内 LAN）。APM は入れない                 |
| 可用性    | 設計は社内業務時間（24/7 必須ではない）。運用は 24 時間付けっぱなし  |


計算（Fargate 0.25 vCPU / 512MB）で足りる規模である。月額で先に効くのはアクセス量ではなく **ALB と RDS を常時置く代**である。

金曜の言い方: 「社内の本棚アプリ。同時は数十人。蔵書は百冊前後。外向けではない。アクセスは少ない。だから置いてある代が先に効く。」

**夜間停止はしない。** 朝起こす仕事が増え、ALB の代は残る。24 時間運転のまま置く。

### 運用方法

アプリの画面操作は同じ。違うのは **箱の手入れ** である。


| 作業         | AWS（24 時間）               |
| ---------- | ------------------------ |
| 日々の入り方     | OS に SSH しない。コンソールか CLI  |
| アプリの反映     | イメージをビルドしてタスク更新          |
| 秘密の変更      | Secrets Manager を直してタスクを再起動 |
| ログ         | CloudWatch               |
| 期限切れ Slack | コンテナ内の毎分                 |
| OS パッチ     | Fargate / RDS は AWS 側    |
| DB バックアップ  | RDS の自動（1 日）             |
| HTTPS      | ALB + ACM                |
| 死活         | `/up`                    |
| 夜間・休日      | 付けっぱなし（停止しない）            |
| 障害         | 入口・計算・DB を分けて見る          |
| 完全に止める     | `cdk destroy`（データも消える定義） |


金曜の言い方: 「社員から見える使い方は同じ。1 台に入って手入れする形は採らない。夜間停止はしない。」

**ほぼ放置でいいのは AWS の 24 時間運転である。** OS パッチと MySQL の箱は AWS 側。SSH しない。アプリの更新（機能追加・脆弱性）は放置できない。課金を止めるなら `cdk destroy` が必要である。

### AWS のメリット

AWS を選ぶ理由は料金ではない。**箱を分けて、OS を自分で見なくてよくする** ことである。


| メリット          | 中身                                                        |
| ------------- | --------------------------------------------------------- |
| 役割が分かれる       | 入口・計算・DB・秘密・ログが別サービス。Web を直しても DB のファイルは同じディスクに無い         |
| DB を外に出さない    | RDS は分離サブネット。3306 は Fargate からだけ。1 台構成はやられると Web も DB も一緒 |
| OS パッチ        | Fargate と RDS の OS は AWS 側。1 台構成は `apt` と再起動が自分の仕事        |
| 秘密をディスクに置かない  | Secrets Manager。コンテナを作り直しても `.env` ファイルが残らない              |
| ログがコンテナごと消えない | CloudWatch。1 台構成はディスクの `laravel.log`                      |
| 同じ定義で作り直せる    | CDK。壊れたら作り直す。`cdk destroy` で課金を止められる                      |
| 後から足せる        | 台数、DB サイズをサービス単位で足せる。いまは最小のまま置いている                        |
| 社内の AWS の話と揃う | 内部開発が AWS を調べている。図書アプリはその実例になる                             |


メリットにしないこと: **安さ**。最小でも月 約 8,000〜11,000 円。RDS は 1 AZ なので、その AZ が止まると DB も止まる。

### 攻撃されるか

**インターネットに出した入口は、探される。** ボットが 80 番をなでるのは普通である。探されることと、入られることは別である。

いまの定義で外から届くのは **ALB の 443（と、443 へ送る 80）** である。Fargate は ALB からしか 80 を受けない。RDS の 3306 はアプリからだけ。SSH で OS に入る箱は無い。パスワードは Secrets Manager で、イメージに焼かない。ログインは HTTPS なので、回線上は暗号化される。

アプリ側はログイン失敗 5 回でロック、CSRF、SQL はバインド、借りる／返すの場所制限はサーバー側である。公開 REST API は出していない。

いま弱いところ:

- **WAF は付けていない**。ボットのなで方は ALB の前で止めていない
- ログイン画面はインターネットから見える。社内 IP 制限は借りる／返す用で、ログイン全体を閉じてはいない
- 証明書用の **公開ドメイン** がまだ無いとデプロイできない（`infra/cdk.json` の `domainName`）

1 台構成も、公開 HTTPS は同じように探される。加えて **SSH（22）** がその 1 台に付くことが多い。やられるとその台の Web も MySQL も一緒である。AWS 側は DB が別サブネットなので、入口だけが探されても 3306 は外から開いていない。

金曜の言い方: 「置いた瞬間からボットは来る。入口は HTTPS。DB と秘密は外に出していない。」

## 3. デプロイするとき（未実施）

必要: AWS アカウント、請求の許可、**公開できるドメイン**、ローカルに Node.js 20 以上・Docker・AWS CLI。

`infra/cdk.json` の `context.domainName` にホスト名を入れる（例: `library.example.co.jp`）。Route53 にゾーンがあるときは `hostedZoneName` も入れる。証明書を既に持っているときは `certificateArn`。ACM の証明書は無料である。

```bash
cd infra
# cdk.json の domainName を実ドメインにする
npm ci
export CDK_DEFAULT_REGION=ap-northeast-1
aws sts get-caller-identity
npx cdk bootstrap aws://アカウントID/ap-northeast-1
npx cdk synth
# 許可が出てから:
# npx cdk deploy
```

`cdk deploy` は Docker でイメージをビルドして ECR に載せる。初回は数十分かかることがある。Route53 を使わないときは、ACM が示す CNAME をドメイン側に入れ、ALB の DNS 名へホスト名を向ける。証明書の検証が終わるまで 443 は使えない。

デプロイ後:

1. CloudFormation 出力の `AppUrl`（`https://…`）を開く（死活は `/up`）
2. 初回だけマイグレーションする（毎回の起動では走らせない）

```bash
# クラスタ名・サービス名は cdk の出力
aws ecs execute-command --cluster <ClusterName> --task <タスクID> \
  --container web --interactive --command "php artisan migrate --force"
```

`execute-command` を使う場合は、デプロイ後に ECS Exec を有効化する必要がある。使えないときは、同じイメージでワンショットタスクを `aws ecs run-task` する。

1. 場所制限の社内 CIDR をタスクの環境変数 `RETURN_ALLOWED_NETWORKS` に入れる
2. メール・Slack は Secrets / 環境変数に後から足す（SES は使わない）

壊して課金を止める:

```bash
cd infra
npx cdk destroy
```

RDS の `removalPolicy` は DESTROY。実データがある状態で destroy すると消える。
