## 1. 仕組み

未処理の例外が発生すると、Laravel 標準の Exception Handler が次を行う。

1. **記録:** 本サーバーは CloudWatch Logs（`LOG_CHANNEL=stderr`。スタックトレース付き）
2. **画面:** 本番（`APP_DEBUG=false`）は汎用のエラー画面。詳細は利用者に出さない

専用クラス `app/Exceptions/Handler.php` は無い。設定は `bootstrap/app.php` の `withExceptions`（`api/*` のとき JSON にする程度）。業務の本線は Inertia の Web である。

| 種類 | 扱い | ログに残るか |
|------|------|----------------|
| 未処理例外（500） | Handler が記録してエラー画面 | **残る** |
| バリデーション | フォームに戻す / Inertia の `errors` | 通常は残らない |
| 業務メッセージ | フラッシュ `error_message`（場所制限など） | 残らない |
| 画面の JS | ブラウザの Console | サーバーログには出ない |
| 表紙画像の読み込み失敗 | `onError` で別 URL を試す | アプリ例外ではない |

Slack の期限切れ通知は障害トラッキングではない（[外部サービスAPI](./外部サービスAPI.md)）。

---

## 2. 使わないもの

| 製品 | 使用 |
|------|------|
| Sentry / Bugsnag / Rollbar / GlitchTip | 使わない（SDK 未導入） |
| CloudWatch アラーム（本サーバー） | 使わない |
| React Error Boundary からのサーバー送信 | 無い |

検知は **人がログを見る**（[バグ対応書](./バグ対応書.md)、[保守運用手順書](./保守運用手順書.md) の週次 ERROR 確認）。

---

## 3. 運用

| 環境 | やり方 |
|------|--------|
| 本サーバー | CloudWatch Logs で `ERROR`。`APP_DEBUG=false` |

パスワードや Token を例外メッセージに出さない。本番で `APP_DEBUG=true` にしない。
