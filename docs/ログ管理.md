# 社内図書貸出管理システム ログ管理

| 項目 | 内容 |
|------|------|
| 対象 | 開発担当・運用担当 |
| 最終更新 | 2026年9月 |

**本サーバーのアプリログは CloudWatch Logs である**（`LOG_CHANNEL=stderr`）。ELK、Datadog、Sentry は使わない。手順は [AWSセットアップ](./AWSセットアップ.md)（未デプロイ）。Linux 1 台の `laravel.log` は本サーバーの正ではない。

---

## 1. 何を使うか

| 環境 | アプリログ | 集約サービス |
|------|------------|--------------|
| **本サーバー（AWS）** | 標準エラー（`LOG_CHANNEL=stderr`） | CloudWatch Logs |

加えて、ALB とコンテナの標準出力がある。フロントの JS エラーはブラウザの開発者ツールだけである。

ライブラリは Laravel 同梱の **Monolog** である。`config/logging.php`。

---

## 2. 使わないもの

| 製品 | 本サーバー |
|------|------------|
| Amazon CloudWatch Logs / Metrics | Logs を使う（未デプロイ）。Metrics / アラームは未導入 |
| ELK（Elasticsearch / Logstash / Kibana） | 使わない |
| Sentry / Bugsnag / Rollbar | 使わない（Composer / npm にも入れていない） |
| Laravel の `LOG_CHANNEL=slack` | 使っていない（期限切れ Slack は別経路） |

例外の記録の流れは [エラートラッキング.md](./エラートラッキング.md) です。

期限切れの Slack 通知はログ基盤ではない。Webhook / Bot で業務通知する（[外部サービスAPI](./外部サービスAPI.md)）。

---

## 3. 本サーバーの運用

| 項目 | 内容 |
|------|------|
| 推奨 | `LOG_CHANNEL=stderr`、`LOG_LEVEL=info` |
| 見方 | CloudWatch Logs の ECS タスクロググループ（保持 3 日の定義） |
| 避ける | 本サーバーでファイルの `single` / `stack`（コンテナが消えると残らない） |

パスワードや Token をログに出さない。`APP_DEBUG=true` の本番は禁止（例外に内部情報が出る）。
